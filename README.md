# Course Templates — EE10

Every form a team fills in during the semester, in Markdown so they can be
committed, diffed, and reviewed alongside the rest of the project.

| File | Used in | Purpose |
|---|---|---|
| `proposal.md` | Week 4–5 | The full research project proposal submitted before the proposal defence. |
| `novelty-statement.md` | Week 4 | Three claims — new approach, new implementation, new evidence — each tied to cited prior art. |
| `impact-30-scoresheet.md` | Week 3 | Scores each shortlisted concept 1–5 on six criteria. Minimum 22/30 to proceed. |
| `pugh-matrix.md` | Week 3 | Concept comparison against the best existing solution as datum. |
| `sourcing-worksheet.md` | Week 3, 10 | Component list with suppliers, lead times, and second-source options. |
| `requirements-specifications.md` | Week 9–10 | Measurable specifications with a verification method for each requirement. |
| `vv-plan.md` | Week 9–10 | The verification and validation plan, including the reference instrument. |
| `engineering-logbook.md` | Weeks 11–14 | Dated entries for every experiment, failure, measurement, and decision. |
| `calibration-report.md` | Week 13 | Calibration curve, error metrics, agreement analysis, and uncertainty budget. |
| `referee-report.md` | Weeks 8, 14 | The mock referee report exchanged between teams before submission. |
| `submission-checklist.md` | Weeks 8, 14 | Everything that must be true before a manuscript is submitted. |

## How to use these

1. Copy the template into your team's own folder or repository.
2. Fill it in. Do not delete headings you have not reached yet — leave them
   marked `TBD` so the reviewer can see what is still outstanding.
3. Commit it. The version history is itself evidence of individual contribution
   and is drawn upon for the contribution factor described in the syllabus.
